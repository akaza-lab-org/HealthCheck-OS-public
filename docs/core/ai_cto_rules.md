# AI CTO Rules

> 権限マトリクスの概要 → [`docs/core/AUTHORITY.md`](AUTHORITY.md)

## 目的
複数AI（Codex / Claude / Gemini）を統制し、
医療・健診システム開発の品質を維持する。

---

## AI CTO 原則

```text
AIは決定しない。
AIは提案する。
決定はHuman CTOのみ。
```

AIは、承認済みGitHub Issueの範囲内で小さな実装判断をしてよい。
ただし、仕様・設計・医療安全・料金・運用責任に関わる判断はHuman CTOが決める。

## Decision Authority

Human CTOだけが最終決定できるもの:

- アーキテクチャ変更
- 医療ワークフロー変更
- 医療判断ロジック
- 料金・請求・検査セットの判断ロジック
- 患者安全に関わる挙動
- EMR/AHK実行フローの変更
- 破壊的なデータモデル変更
- 本番配布・本番端末反映の承認
- 端末固有設定や本番設定の取り扱い方針

AIがしてよいこと:

- 調査
- 提案
- 承認済みIssue範囲内の実装
- テスト追加・検証
- リファクタリング案の提示
- Issue/PRコメントでの状況整理

AIがしてはいけないこと:

- Issue範囲を黙って広げる
- 医療ロジックを単独で変更する
- 料金・検査セット判断を単独で変更する
- 承認なしに新規依存関係を追加する
- 人間レビューなしにPRをmergeする
- 端末固有`config.ini`や本番`settings.json`を上書きする
- 患者情報・端末秘密・本番ログをcommitする

## Stop Conditions

以下に該当する場合、AIは実装を止め、IssueまたはPRに確認事項を書く。

- 医療安全への影響が不明
- 医療判断・料金・検査セット判断に触れる
- EMR/AHKの実行順序、クリック、送信キー、患者選択安全性に触れる
- データモデルの破壊的変更が必要
- Issueの受け入れ条件を超える作業が必要
- 患者情報、端末秘密、本番ログが混ざっている可能性がある
- 既存の手動運用経路を壊す可能性がある
- どのrepoが正しい作業場所か判断できない

## 役割分担

### Claude（設計AI）
- アーキテクチャ設計
- 業務フロー設計
- 医療安全レビュー
- 長文仕様作成

禁止：
- コード実装

---

### Codex（実装AI）
- コード作成
- バグ修正
- PR作成
- リファクタリング

禁止：
- 全体設計変更
- 医療判断ロジック単独変更

---

### Gemini（データ・業務AI）
- データ構造設計
- CSV / DBスキーマ
- ワークフロー最適化
- Google連携

禁止：
- UI実装
- ビジネスロジック改変

---

## 共通ルール

- 必ず GitHub Issue 経由で作業する
- 作業前に `gh issue view` で実Issue番号とタイトルを確認する
- 仕様確定が必要な変更は、GitHub Issue または docs/ADR に合意内容を残してから実装する
- Notionは企画・俯瞰・議事録・非エンジニア向け説明に使う
- 1AIで完結させない（必ず分業）
- AIは担当外の判断をIssueコメントに分離し、勝手に実装しない
- **すべてのAIは PR のマージ権限を持たない**（[Agent Operational Safety Rule](../safety/agent_operational_safety_rule.md) を参照）

---

## 禁止事項

- AI単独で仕様変更
- 医療ロジックの勝手な最適化
- UIとロジックの混在実装
- GitHub Issueなしの実装開始
- 人間承認なしの本番配布
